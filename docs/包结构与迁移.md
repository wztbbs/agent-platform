# 包结构与 0.3.0 迁移

本次只重组 Java 包及其引用，不新增底座能力，不修改数据库 schema、持久化 JSON 字段、运行协议或 Prompt 内容。根包 `com.cexpilot.platform` 和 Maven 坐标 `com.cexpilot:agent-platform` 保持不变，版本更新为 0.3.0。

## 职责边界

| 一级包 | 职责 | 主要子包 |
| --- | --- | --- |
| agent | Agent 契约、定义、注册、路由和宿主执行入口 | routing |
| execution | 目标 Agent 内部的执行引擎、预算与执行结果 | react、plan、dag、config |
| run | 持久化运行、租约、检查点、等待和恢复 | 当前保持平铺 |
| tool | 工具定义、注册、协议适配、计算工具和实际调用 | execution、control、calculation、config |
| llm | 模型协议、客户端、调用服务和诊断 | 当前保持平铺 |
| policy | Agent／工具准入、授权、资源约束及审批 | agent、tool、approval |
| context | 上下文投影、会话读取端口、Prompt 与证据接口 | session、prompt、evidence |
| observability | Trace 生命周期、存储、事件与用量 | 当前保持平铺 |
| configuration | Spring 装配与默认组件配置 | autoconfigure |

跨模块调用不改变职责归属：TraceSink 属于 observability，QueryBudget 属于 execution，RunCheckpoint 属于 run。AgentRunContext 是 Agent 执行契约，仍属于 agent；RequestContext 是一次执行的时间基准，仍属于 execution。不建立 common／shared 包，也不为尚未实现的 Eval 建立空包。

规划与审批明确区分：execution.plan 负责模型规划循环；policy.approval 负责方案冻结、审批和获批约束；tool.execution 负责真正调用工具和执行获批方案。ToolControl 是工具执行语义声明，保留在 tool.control。

## 旧包迁移表

下表均省略 `com.cexpilot.platform.` 前缀。

| 旧位置 | 新位置 |
| --- | --- |
| engine.react、engine.plan、engine.dag | execution.react、execution.plan、execution.dag |
| agent.session | context.session |
| prompt | context.prompt |
| evidence | context.evidence |
| autoconfigure | configuration.autoconfigure |
| agent.IntentRouter | agent.routing.IntentRouter |
| context.DispatchLifecycle、context.RoutingDialect | agent.routing 下同名类型 |
| agent.AgentAccessPolicy、agent.AgentRegistrationPolicy | policy.agent 下同名类型 |
| tool.control.ToolAccessPolicy、ToolResourceGuard、ToolAccessChecks、RegisteredAgentToolPolicy | policy.tool 下同名类型 |
| tool.control.ContentFingerprint | policy.approval.ContentFingerprint |
| tool.control.ToolGateway、tool.control.ToolCallStatus | tool.execution 下同名类型 |
| plan.PreparedPlanExecutor、PlanExecutionResult、PlanExecutionStatus | tool.execution 下同名类型 |
| plan 中其余类型 | policy.approval 下同名类型 |

测试包同步迁移。Spring Boot 的 AutoConfiguration.imports 已更新到新的 TraceAutoConfiguration 全限定名。

## 宿主升级

1. 将 Maven 依赖版本更新为 0.3.0。
2. 按上表更新 import、代码中的全限定名，以及反射、XML、组件扫描和测试配置中显式写出的旧类名。原先通配导入 agent、plan 或 tool.control 的代码需要按新职责分别导入。
3. 清理旧编译产物，重新编译并验证宿主。

公共执行入口 `agent.AgentExecutionService`／`agent.AgentExecutionRequest` 和显式装配入口 `configuration.PlatformConfiguration` 没有迁移。宿主仍通过会话与上下文端口提供业务数据，不改用内部 AgentDispatchRequest 装配请求。

这是公共类型包名变更，不提供旧包兼容包装，旧宿主二进制不能直接替换 JAR 使用。宿主自行选择升级时间，本次不发布或安装制品。0.3.0 没有新增 SQL 迁移；已完成 0.2.0 数据库迁移的宿主不需要重复执行升级 SQL。
