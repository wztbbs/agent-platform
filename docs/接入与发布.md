# 接入与发布

## 工程归属

- Agent Platform 独立构建、测试和发布，使用自己的版本号。
- 宿主应用提供业务 Agent、工具、Prompt、HTTP 入口及身份来源；库只提供通用协议和实现。
- 独立工程不依赖某个客户项目的父 POM，所有依赖由公开 Spring Boot BOM 和本工程 POM 声明。
- 当前普通 JAR 没有配置 Spring Boot repackage，不是可执行应用，也不作为独立进程部署。

## Spring 接入

```java
@SpringBootApplication
@Import(PlatformConfiguration.class)
public class BusinessApplication {
    public static void main(String[] args) {
        SpringApplication.run(BusinessApplication.class, args);
    }
}
```

宿主必须配置支持运行表 DDL 的 DataSource，并提供 ObjectMapper、名为 normalLlmClient 的 LlmClient 与 ToolEvidenceWriter。默认 UTC Clock 和数据库 TraceSink 由底座装配，可通过宿主 Bean 替换。Spring Boot 可以根据 Jackson/JDBC 配置自动提供部分基础设施；模型凭证、业务身份及证据保存必须由宿主决定。

通过业务 Bean 或 agents/*.yml 注册 Agent，工具定义位于 tools/*.yml。公共计算工具和引擎模板已在本 JAR 中，不能复制同名定义造成重复注册。上下文、路由方言、交接、权限和资源版本检查按需实现对应端口。带私有输入输出及业务结果提交的 Agent 提供 AgentRunAdapter。

组件仍通过显式 PlatformConfiguration 装配；TraceAutoConfiguration 只补齐缺省 Clock／TraceSink，不创建数据库或加载业务配置。请求使用 AgentExecutionService，业务会话规则通过 AgentSessionProvider 提供，详见[执行入口与 Trace](执行入口与Trace.md)。

## 数据库

公共 schema 位于 `src/main/resources/platform/db/schema.sql`，包含 platform_run、platform_tool_call、platform_run_checkpoint、platform_prepared_plan，以及 ask_trace、trace_event，共六张表。宿主显式执行 `classpath:platform/db/schema.sql`，再初始化自己的业务表。

库本身不执行数据库初始化。已有表的变更应发布升级脚本并由宿主部署流程执行，不能用 CREATE TABLE IF NOT EXISTS 替代结构升级。

0.2.0 的存量 Trace 数据库需额外执行 `platform/db/migrations/002_trace_request_context.sql`，增加 UTC 请求开始时间和上游关联 ID；保留旧表名及已有数据。新库只执行完整 schema，不重放该迁移。

## 发布

1. 修改公共 API、行为或数据库结构后，明确版本及兼容性。
2. 先编译，再运行变更直接涉及的测试。
3. 构建普通 JAR 和同版本 POM，发布至 Maven 私服；尚未建立私服时使用 README 中的发布包及 install-file。
4. 宿主独立选择升级版本并完成业务验证，不要求不同客户同步部署。

POM 必须随 JAR 一起发布。消费者解析依赖时需要其中的公开父 POM和传递依赖信息，不能仅复制一个 JAR 或沿用 CEX 的父 POM。

## 0.3.0 包结构迁移

0.3.0 重组 Java 子包，不新增执行能力，不修改数据库 schema 或运行协议。宿主需要更新 import、全限定类名及自定义扫描配置后重新编译；完整映射见[包结构与迁移](包结构与迁移.md)。公共入口仍为 `com.cexpilot.platform.agent.AgentExecutionService`，显式装配入口仍为 `com.cexpilot.platform.configuration.PlatformConfiguration`。
